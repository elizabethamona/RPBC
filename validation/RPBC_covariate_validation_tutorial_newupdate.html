1 Purpose

This tutorial documents the statistical motivation, implementation, and controlled numerical validation of the covariate-adjusted Region-Preserving Batch Correction (RPBC) engine.

The goal is not merely to show that the code runs. The tutorial connects the covariate-adjusted implementation directly to the mathematical structure of RPBC and asks whether the software behaves consistently with the intended preservation target and identifying restrictions.

The central questions are:

  • How does covariate-adjusted RPBC extend ordinary RPBC?
  • Why are patient-level covariates included in the protected location component?
  • Why is the residual patient effect restricted to the orthogonal complement of the covariate space?
  • Does the implementation construct the patient-level covariate design correctly?
  • Does it enforce (X_0^T_g=0) numerically?
  • Does it retain the usual sum-to-zero constraint for the patient-by-region interaction?
  • Does the constrained empirical-Bayes update preserve those restrictions after estimation?
  • Does the harmonized output preserve dimensions, names, and finite values?
  • Does covariate-adjusted RPBC continue to use the ordinary RPBC scale update rather than the Adaptive stabilization rule?

Important: These controlled examples provide implementation-level numerical validation. They complement, but do not replace, the mathematical results, simulation studies, and real-data analyses in the RPBC manuscript.

3 Statistical Model

For feature (g), patient (p), region (r), and cell (j), the covariate-adjusted RPBC location-scale model is

[ Y_{prjg} = g + {Rg}R_r + x_p^T{Xg} + {pg} + {pg}R_r + {pr,g}_{prjg}. ]

Here:

  • (_g) is the feature-specific intercept;
  • (R_r{-1,+1}) codes Core and Edge;
  • (x_p) is the vector of patient-level covariates;
  • (_{Xg}) contains the systematic covariate coefficients;
  • (_{pg}) is the residual patient-specific nuisance effect;
  • (_{pg}) is the patient-specific deviation from the population-average regional effect;
  • (_{pr,g}^2) is the patient-region residual variance multiplier.

The population-average regional effect remains represented by (_{Rg}).

4 What Covariate Adjustment Changes

Ordinary RPBC protects

[ g+{Rg}R_r. ]

Covariate-adjusted RPBC instead protects

[ g+{Rg}R_r+x_p^T_{Xg}. ]

This distinction is fundamental.

A patient-level variable such as age or sex may explain systematic biological or clinical variation. If that systematic variation is included as a prespecified covariate, it should not be absorbed into the nuisance patient effect and removed during harmonization.

5 Why the Covariate Matrix Is Centered

Let (X) denote the patient-level covariate design after categorical variables have been expanded.

RPBC centers every column of (X) equally across patients. The augmented patient-level design is then

[ X_0=[,X]. ]

Centering makes the covariate columns orthogonal to the intercept in the patient-balanced design and gives the intercept a clear population-average interpretation.

This is a patient-level operation. A patient with many cells should not receive more weight in the centering step simply because more cells were observed.

6 Why the Residual Patient Effect Must Be Orthogonal to the Covariates

If the residual patient effect were unrestricted, it could reproduce variation already represented by the intercept and covariates.

That would make the decomposition between

[ x_p^T_{Xg} ]

and

[ _{pg} ]

non-identifiable.

Covariate-adjusted RPBC therefore imposes

[ X_0^T_g=0. ]

The residual patient effect is parameterized in

[ (X_0^T). ]

This means that (_g) contains only patient-specific variation that cannot be represented by the protected intercept/covariate space.

The patient-by-region interaction retains the ordinary RPBC restriction

[ p {pg}=0. ]

7 Why Covariate-Adjusted RPBC Is Still RPBC

Covariate-adjusted RPBC is not a separate public method. It is the same RPBC framework with an optional patient-level systematic component.

Conceptually:

[ = \[\begin{cases} \text{ordinary RPBC}, & \text{if covariates are absent},\\ \text{covariate-adjusted RPBC}, & \text{if covariates are supplied}. \end{cases}\]

]

In the package engine this is implemented through

covariates = NULL

for ordinary RPBC and a supplied patient-level covariate object for the adjusted analysis.

# Scale Estimation: Why This Is Not Adaptive RPBC

Covariate adjustment changes the **location decomposition and identifying restriction**.

It does not, by itself, change the ordinary RPBC patient-region scale update.

Therefore this engine uses the ordinary empirical-Bayes update for

\[
\delta_{pr,g}^2
\]

without the group-size-dependent stabilization used by Adaptive RPBC.

This distinction is intentional:

- ordinary RPBC: ordinary location structure and ordinary scale update;
- covariate-adjusted RPBC: covariate-adjusted location structure and ordinary scale update;
- Adaptive RPBC: Adaptive scale stabilization handled by the separate Adaptive engine.

This keeps the two extensions conceptually distinct.

# Harmonization

On the standardized scale, the nuisance location for patient \(p\), region \(r\), and feature \(g\) is

\[
\gamma_{pg}^*
+
\kappa_{pg}^*R_r.
\]

The engine removes this nuisance component and divides by the square root of the posterior patient-region variance multiplier.

The result is then returned to the original feature scale and the complete protected mean is restored:

\[
\alpha_g
+
\beta_{Rg}R_r
+
x_p^T\beta_{Xg}.
\]

This is the defining preservation step of covariate-adjusted RPBC.

20 Interpretation of the Validation

The controlled example establishes the following implementation properties:

  1. Covariate recognition
    The engine correctly recognizes supplied patient-level covariates and switches to the covariate-adjusted branch.

  2. Patient-balanced coding
    Covariate columns are centered across patients rather than weighted by cell counts.

  3. Null-space construction
    The residual patient basis satisfies

    [ X_0^TQ_. ]

  4. Initial identifiability
    The initial residual patient effects satisfy

    [ X_0^T_g. ]

  5. Posterior identifiability
    The constrained empirical-Bayes estimates satisfy

    [ X_0^T_g^*. ]

  6. Interaction identifiability
    Both initial and posterior patient-by-region effects satisfy their sum-to-zero restriction.

  7. Full-rank estimation
    Both the location design and identifying constraint matrix have the required ranks.

  8. Protected covariate component
    The systematic patient-level covariate contribution is retained in the protected mean instead of being removed as nuisance variation.

  9. Ordinary scale update retained
    Covariate adjustment does not invoke the Adaptive variance-stabilization mechanism.

  10. Output integrity
    The harmonized matrix retains the input dimensions and names and contains finite values.

21 Final Validation Summary

The covariate-adjusted RPBC engine is numerically consistent with the intended model structure:

[ Y_{prjg} = g + {Rg}R_r + x_p^T{Xg} + {pg} + {pg}R_r + {pr,g}_{prjg}, ]

with protected location component

[ g + {Rg}R_r + x_p^T_{Xg}, ]

and identifying restrictions

[ X_0^T_g=0 ]

and

[ p{pg}=0. ]

The validation therefore supports the implementation of covariate-adjusted RPBC as a unified extension of ordinary RPBC in which prespecified patient-level systematic variation is preserved while residual patient and patient-by-region nuisance effects are harmonized.
