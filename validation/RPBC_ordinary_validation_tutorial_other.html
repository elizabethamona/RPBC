Does the implementation do what the method claims?

This report records the controlled toy examples, R code, observed numerical outputs, and interpretations used while validating the ordinary RPBC statistical engine.

How to read this report

Each validation check is organized around four items: question, code, observed output, and interpretation. The purpose is not merely to show that the code runs, but to show that the implementation behaves in a way that is consistent with the intended RPBC statistical targets.

Important: These toy examples provide controlled numerical evidence for the implementation. They complement, but do not replace, the mathematical results and broader simulation/real-data evaluation in the manuscript.

Toy example 1 — patient-wide nuisance location shifts

Scientific question. Can ordinary RPBC reduce artificial patient-wide nuisance shifts while preserving the population-average Core–Edge signal?

The simulated data contain 6 generic molecular features measured across 40 cells from 4 patients. Each patient contributes Core and Edge cells. A population-average regional signal is introduced by adding +0.8 to Edge and −0.8 to Core, so the intended Edge − Core separation is about 1.6 before sampling noise. Patient-wide nuisance shifts are then deliberately added.

Data-generation and model-fitting code

set.seed(2026)

patient <- rep(paste0("P", 1:4), each = 10)

region <- rep(
  rep(c("Core", "Edge"), each = 5),
  times = 4
)

dat_test <- matrix(
  rnorm(6 * 40, mean = 0, sd = 0.5),
  nrow = 6,
  ncol = 40
)

rownames(dat_test) <- paste0("Feature", 1:6)
colnames(dat_test) <- paste0("Cell", 1:40)

dat_test <- sweep(
  dat_test,
  MARGIN = 1,
  STATS = seq(1, 6),
  FUN = "+"
)

# Population-average regional signal:
# Edge = +0.8, Core = -0.8
dat_test <- sweep(
  dat_test,
  MARGIN = 2,
  STATS = ifelse(region == "Edge", 0.8, -0.8),
  FUN = "+"
)

# Patient-wide nuisance location shifts
patient_shift <- c(
  P1 = -0.7,
  P2 = 0.4,
  P3 = 1.0,
  P4 = -0.7
)

dat_test <- sweep(
  dat_test,
  MARGIN = 2,
  STATS = patient_shift[patient],
  FUN = "+"
)

fit_test <- .rpbc_fit_matrix(
  dat = dat_test,
  patient = patient,
  region = region
)

Identifiability check

Question. Do the posterior patient effects and patient×region interaction effects satisfy the RPBC sum-to-zero constraints?

Σp γpg = 0     and     Σp κpg = 0

Code

colSums(fit_test$gamma_star)
colSums(fit_test$kappa_star)

Observed output

The column sums were numerically zero up to floating-point precision: approximately order 10−16 for γ and 10−17 for κ.

Interpretation: The constrained empirical-Bayes update is enforcing the intended identifiability conditions computationally. Tiny values on the order of 10−16 are ordinary machine-precision rounding error, not meaningful violations.

Preservation of the patient-balanced Core–Edge contrast

Question. After harmonization, is the patient-balanced population-average regional contrast retained?

Code

patient_balanced_contrast <- function(x, patient, region) {

  per_patient <- sapply(
    unique(patient),
    function(p) {
      rowMeans(
        x[, patient == p & region == "Edge", drop = FALSE]
      ) -
      rowMeans(
        x[, patient == p & region == "Core", drop = FALSE]
      )
    }
  )

  rowMeans(per_patient)
}

contrast_before <- patient_balanced_contrast(
  dat_test, patient, region
)

contrast_after <- patient_balanced_contrast(
  fit_test$data, patient, region
)

cbind(
  before = contrast_before,
  after  = contrast_after
)

Reduction of patient-wide nuisance location variation

Question. Does RPBC reduce the artificial patient-to-patient nuisance shifts represented by γpg?

patient_feature_means <- function(x, patient) {

  sapply(
    unique(patient),
    function(p) {

        x[, patient == p, drop = FALSE]

Toy example 2 — patient-region scale heterogeneity

Scientific question. Does the δpr,g2 part of ordinary RPBC harmonize deliberately unequal patient-region variances without destroying the protected regional mean effect?

This dataset contains 6 features and 80 cells. In addition to patient-wide location shifts and the same Core–Edge signal, each patient-region group is assigned a deliberately different standard deviation, ranging from 0.30 to 1.50.

Data-generation and model-fitting code

set.seed(2027)

patient2 <- rep(
  paste0("P", 1:4),
  each = 20
)

region2 <- rep(
  rep(c("Core", "Edge"), each = 10),
  times = 4
)

group_sd <- c(
  "P1_Core" = 0.30,
  "P1_Edge" = 1.20,
  "P2_Core" = 0.60,
  "P2_Edge" = 1.50,
  "P3_Core" = 1.30,
  "P3_Edge" = 0.40,
  "P4_Core" = 0.80,
  "P4_Edge" = 1.10
)

patient_shift2 <- c(
  P1 = -0.8,
  P2 = 0.3,
  P3 = 1.0,
  P4 = -0.5
)

dat_scale_test <- matrix(
  0,
  nrow = 6,
  ncol = length(patient2)
)

rownames(dat_scale_test) <- paste0("Feature", 1:6)
colnames(dat_scale_test) <- paste0("Cell", seq_len(ncol(dat_scale_test)))

for (j in seq_len(ncol(dat_scale_test))) {

  p <- patient2[j]
  r <- region2[j]

  sd_j <- group_sd[paste0(p, "_", r)]

  biological_region_effect <- ifelse(
    r == "Edge",
    0.8,
    -0.8
  )

  dat_scale_test[, j] <- seq(1, 6) +
    biological_region_effect +
    patient_shift2[p] +
    rnorm(6, mean = 0, sd = sd_j)
}

fit_scale_test <- .rpbc_fit_matrix(
  dat = dat_scale_test,
  patient = patient2,
  region = region2
)

Convergence

fit_scale_test$converged
# [1] TRUE TRUE TRUE TRUE TRUE TRUE

fit_scale_test$iterations
# [1] 4 5 5 4 5 5
Interpretation: All six features converged successfully despite strong group-specific scale heterogeneity.

Direct check of patient-region scale harmonization

Question. Are the deliberately heterogeneous patient-region standard deviations made more comparable after RPBC?

Code

patient_region2 <- interaction(
  patient2,
  region2,
  sep = "_",
  drop = TRUE
)

group_variance <- function(x, group) {

  sapply(
    levels(group),
    function(gr) {
      matrixStats::rowVars(
        x[, group == gr, drop = FALSE]
      )
    }
  )
}

variance_before <- group_variance(
  dat_scale_test,
  patient_region2
)

variance_after <- group_variance(
  fit_scale_test$data,
  patient_region2
)

cbind(
  SD_before = sqrt(colMeans(variance_before)),
  SD_after  = sqrt(colMeans(variance_after))
)

Where this fits in package development

This HTML report is a human-readable validation tutorial. It is distinct from the permanent automated tests that will live under tests/testthat/. The automated tests will protect the package against future regressions; this report explains the statistical meaning of those checks for collaborators, supervisors, reviewers, and future users.

A later vignette can reuse a cleaner subset of this material, but the vignette should focus on teaching users how to use RPBC rather than documenting every internal development check.
